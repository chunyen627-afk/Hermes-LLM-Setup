# RTX 5080 珍珠挖礦部署與交接

更新：2026-10-24。此為單張 RTX 5080 Windows 主機的實測與可重建腳本快照；不是三卡主機或雙2060的配置。
本次只更新文件與去識別的腳本，沒有改動或重啟正在運行的本機礦工。

## 使用者最後選擇

- 桌面單一「珍珠挖礦」捷徑，手動開始；不設定開機自動挖礦、不自動重啟。
- 以較安靜、約180～185 TH/s為調校目標；放棄為200 TH/s大幅增加風扇噪音。
- 250W功率上限、2300MHz核心鎖定目標，不加額外核心偏移，不鎖顯存頻率。
- 核心65°C起每次輪詢降低150MHz目標（最低600MHz），本輪只降不升；70°C停止。每約2秒檢查，不能保證取樣間隔內毫無瞬間超溫。
- 重新啟動前必須低於60°C。使用者打算24小時運行，尚未完成24小時穩定驗證。
- 挖礦時退出MSI Afterburner（小飛機），由腳本接管；停止後解除鎖頻、恢復原功率與自動風扇，再啟動小飛機並套用原有Profile 1。
- 監控服務曾試建後由使用者取消：已停止、移除專用防火牆規則，無監控自啟排程；此目錄不包含集中監控服務。

## 環境與適用範圍

- NVIDIA GeForce RTX 5080 16GB，驅動616.92，三個可由NVML控制的風扇。
- 此卡讀到功率範圍250～400W、出廠預設360W、部署前有效上限400W。這些是本卡讀值，不代表其他5080。
- 電源供應器瓦數未知；沒有將功率提高至400W做滿載挖礦驗證。
- KRig 1.5.12；Python 3.12.14、pywin32 312、nvidia-ml-py 13.615.71。
- 預留6144MiB的啟動顯存門檻是因本機桌面程式占用較多；不能當成沒有遊戲／AI使用GPU的證明。
- 私人Mining Username、GPU UUID及使用者路徑需在本機填入，不提交GitHub。

## 實測摘要

以下為短測、礦工本機輸出；功耗僅GPU，並非插座整機功耗。不同輪次的起始溫度、風扇曲線和負載並不完全相同。

| 設定／測試 | 本機算力 | GPU功耗 | 核心溫度／風扇 | 結論 |
|---|---:|---:|---|---|
| 1500MHz、250W上限 | 約120～121 TH/s | 約137～140W | 約46～48°C，較積極曲線 | 初步低頻基準 |
| 1800MHz、250W上限 | 約145 TH/s | 約166W | 約50°C | 低功耗候選 |
| 2100MHz、250W上限 | 約167～169 TH/s | 約196W | 約54°C，較積極曲線 | 較省電候選 |
| **2300MHz、250W上限、降噪曲線** | **約178～185 TH/s，多數182～185** | **約224～240W** | **五分鐘內最高63°C；熱起來後風扇約65～73%** | **使用者選定** |
| 2400／2700MHz目標、250W上限 | 約186～188 TH/s | 約250W | 約60～61°C，原積極曲線約90～92% | 功率受限，拉高目標增益有限 |

| 2600MHz目標、275W、67°C降頻及效能風扇 | 約192～193 TH/s | 約274～275W | 約63～65°C、97～100%風扇 | 使用者取消此方向，回到較安靜檔 |

選定2300MHz檔的五分鐘短測有4個accepted、0 stale、0 rejected。先前五檔比較有6個accepted、0 stale、0 rejected。
之後運行可見核心約2137MHz、算力約167～173 TH/s、202～207W、59～60°C，符合本輪降頻後不自動升頻的行為；
不能把180～185 TH/s當成全天保證。更低算力本身不代表斷線，應一起確認accepted持續增加與停止紀錄。

## 風扇與保護

正式採用的分段線性曲線：35°C/40%、50°C/50%、60°C/65%、65°C/80%、69°C/100%。
開始時先設定45%並等待，運行後依溫度逐風扇設定與讀回；控制失敗停止。
高風扇`performance`模式、67°C降頻點、275W上限、核心偏移與顯存鎖頻僅保留為測試能力，**不在範本中啟用**。

- Windows Job Object在礦工仍暫停時先納管，再恢復執行；關閉監護程序時會終止所屬礦工。
- 獨立復原程序持有監護程序handle；意外關窗／強制終止後解除本次鎖頻、恢復功率與風扇，重開小飛機Profile 1。
- 正常Ctrl+C停止與強制終止復原已在本機測試。斷電或整個作業系統崩潰不在使用者態復原保證內。
- 15分鐘無新的accepted、礦工退出、GPU辨識／讀值／設定不符皆停止。份額有隨機性，無份額門檻可能誤停。
- 挖礦期間呼叫Windows防休眠；結束解除，不改原電源計畫。
- 本機原小飛機設定已備份；這套交接以原有Profile 1為準。新機若Profile 1不同或有其他自訂鎖頻，必須重新規劃還原，不能照抄。

## 重建步驟

1. 保留原AI模型，備份本機NVIDIA狀態、Afterburner主設定與Profiles。確認沒有既有礦工／遊戲／AI負載。
2. 將此目錄放到固定資料夾（以下稱`Pearl-mining`）。檢查`session.py`中的Afterburner標準安裝路徑與Profile 1是否適用。
3. 建立Python環境、安裝依賴：

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   Copy-Item config.example.json config.local.json
   ```

4. 自[官方KRig 1.5.12版本](https://github.com/kryptex-miners-org/kryptex-miners/releases/download/krig-1-5-12/krig-miner-1.5.12-win-x64.zip)下載ZIP。
   SHA256必須是`c4342a413e5c244d9fcc288b2e515b2fed468b262c7393b723ace30e25f077f3`，解壓後放`runtime/krig-miner.exe`。
   不使用附帶帳號範例、不停用防毒來強行安裝。
5. 填自己的Mining Username、實機UUID／index；本機worker為`rtx5080`。確認本卡允許功率、風扇控制與原設定備份後，才把`validated_for_this_machine`改為true做有人監看的短測。
6. 執行純檢查：`.\.venv\Scripts\python.exe -m unittest discover -p test_guard.py`。此套9項測試包含70°C門檻、NaN感測值、GPU錯配、暫停子程序納管與未驗證範本禁止觸碰GPU；不代表熱測通過。
7. 建立桌面「珍珠挖礦」捷徑指向`START.bat`，或指向`powershell.exe -NoProfile -ExecutionPolicy Bypass -File "完整路徑\launch.ps1"`。需接受Windows管理員提示。
8. 開始前確認低於60°C；看`Total`、accepted、溫度及風扇。Ctrl+C或關窗停止，驗證小飛機接手。

此快照相較當時本機版本，額外增加「未完成本機驗證就拒絕啟動」的前置檢查，避免範本在尚未設定時先觸碰GPU。
它沒有自動部署到正在挖礦的本機。

## 檔案與後續觀察

- `START.bat` → `launch.ps1`（UAC）→ `session.py`（接管／復原）→ `portable_guard.py`（礦工與熱保護）。
- `logs/mining-*.log`：算力與accepted/stale/rejected；`gpu-*.jsonl`：GPU溫度／功率等；`result-*.json`：有正常寫出的停止原因。
- `power-*.json`及`.ready/.restored/.error`：復原程序狀態。直接強制結束可能沒有`result`，不能憑空判定是主動停止或異常。
- GitHub不包含帳號、錢包、Token、UUID、主機名稱／IP、原始LOG、私人設定、備份、venv或執行檔。
- 尚待完成24小時穩定觀察與插座整機功耗量測。兩段式電價與收益討論屬當時估算，不能取代單機實際入帳；不設定尖離峰自動切換，也不自動提領。
