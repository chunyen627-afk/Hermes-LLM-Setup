# 硬體除錯通用手冊

**先問一個問題：這是軟體問題還是硬體問題？**

分辨方法：**同樣的操作，結果會不會變？**
- 每次都一樣 → 多半是軟體/設定
- 時好時壞、換條線就不同 → 多半是硬體

---

## 一、接不上（除錯器 / 序列埠）

照順序查：

1. **埠被佔用** —— 最常見。另一個視窗開著 monitor/terminal 就會鎖住。
   先關掉所有可能連著的程式
2. **選錯埠** —— Windows 看裝置管理員，Linux 看 `dmesg | tail`
3. **線材** —— **很多 USB 線只有電源沒有資料線**。
   換一條確定能傳資料的
4. **驅動** —— CP2102 / CH340 / FTDI 各有各的驅動
5. **電源** —— 見下一節

## 二、電源（最容易被忽略）

**症狀：隨機失敗、燒到一半斷、跑一陣子重開。**

- MCU 的**峰值電流**遠大於平均值（ESP32 峰值 200-300mA）
- **從別的開發板取電通常不夠**（FTDI 小板、Arduino 的 3.3V 輸出帶不動）
- **麵包板接觸電阻**會讓電壓掉下來
- 電容不足 → 瞬間電流拉不上來 → 掉電重開

用萬用電表量**負載時**的電壓，不是空載。掉超過 5% 就有問題。

## 三、燒不進去

| 症狀 | 常見原因 |
|---|---|
| 完全沒反應 | 沒進 bootloader / 下載模式（boot 腳位、手動按鍵）|
| 連上但寫入失敗 | 電源不足、flash 被寫保護、位址錯 |
| **顯示成功但沒生效** | 燒到錯的記憶體（外部 flash 要載入器）、只燒了一半 |
| 中途隨機失敗 | 電源掉、線材差、baud 太高 |

**降 baud 是好用的區分法**：慢速能通就是訊號品質問題，不是邏輯問題。

**燒完一定要讀回驗證**，不要相信「成功」訊息。

## 四、訊號完整性

- **接線越短越好**，尤其高速訊號（SPI、JTAG、時鐘）
- **麵包板不適合高速** —— 寄生電容大，SPI 超過幾 MHz 就開始出錯
- **地線要短要粗**，多接幾條地
- 量測時**探棒的地線也要短**，長地線量出來的雜訊是探棒自己的

## 五、時鐘

時鐘設錯的症狀很有欺騙性：**程式在跑但所有時序都不對**。

- UART 亂碼 → 先懷疑時鐘不是你以為的頻率
  （例：reset 後跑內部 16MHz，但程式碼假設 64MHz → baud 差 4 倍）
- 晶振沒起振 → 有些晶片會自動退回內部 RC，不報錯
- **開機初期和初始化後的時鐘不一樣**，早期的 log 可能是亂碼

## 六、量測工具的可信度

**懷疑資料之前先驗證量測方法。**

- 讀記憶體時 CPU 有沒有被 halt？halt 住會永遠讀到初始值
- 探棒有沒有校正？
- 邏輯分析儀的取樣率夠不夠？（至少訊號頻率的 4 倍）
- 讀回來的值一直是 0 或全 F → 通常是沒讀到，不是真的是那個值

畫一個**已知內容的測試訊號**餵進去，看量到的對不對 —— 
確認工具可信再開始查真正的問題。

## 七、間歇性問題

最難的一類。策略：

1. **先讓它穩定重現** —— 找出觸發條件（溫度？時間？特定操作？）
   不能重現就無法驗證修好了沒
2. **加 log 但不要改變時序** —— 印太多會改變行為（Heisenbug）。
   用 GPIO 翻轉或寫記憶體，不要用 printf
3. **記錄失敗當下的狀態** —— 錯誤計數器、最後執行的階段
