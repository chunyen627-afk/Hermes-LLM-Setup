替使用者送測試訊息給本地 LLM（27B / 30B via Flask）時，**prompt 要白話、模糊、不指定技術細節**。

**Why:** 使用者想驗證模型的「自己思考能力」——能不能從一句口語要求發展出完整作品。如果我把規格寫死（檔案結構、區塊清單、配色細節、互動 UX），就變成測「模型能不能跟我寫的規格」而不是測模型本身。使用者明確說過「我想要讓模型自己思考」。

**How to apply:** 替使用者送本地 LLM 測試 prompt 時：

- ✅ 好：「做個個人作品集網站」/「做個貪食蛇」/「做個 Pac-Man」
- ✅ 可加最低限制：「手機要能看」、「單檔 HTML」
- ❌ 不要列「分 3 個檔：index.html / style.css / main.js」
- ❌ 不要列「至少 4 個區塊」、「配色現代極簡（深色背景、亮綠 accent）」
- ❌ 不要教互動細節「卷動時 nav 變透明黑底」、「滑鼠移上去動畫」
- ❌ 不要規定迷宮尺寸「28x31」、AI 行為「紅 Blinky 追擊 / 粉 Pinky 包圍」

這條只適用於**替使用者發給本地 LLM 的測試訊息**。改 [[mobile-remote-gui]] 後端 WIN_RULES（system prompt）時不適用——WIN_RULES 詳細教工具用法反而是對的。

**2026-08-29 補：寫「任務 .md 檔」也算，形式不同但本質一樣。**
那次出 FIFO 題，我寫了七個測試情境、指定用 `collections.deque` 當參考模型、
規定交付五項清單。使用者當場否決：「太多了，上題也才三行」。

問題在於**我把答案寫進題目了** —— 邊界條件在哪、驗證方法該用什麼，
那正是要測它會不會自己想到的東西。它照做完，我只知道它會照做，不知道它會不會想。

對照組：上一題只給三行「做一個數位電路，跑模擬，看波形，自己確認它對不對」，
它自己想出用獨立 Python 程式從波形反推位元來驗證（`recon.py`），
**比我能指定的方法還好**。

可以保留的最低限度是「限定題型難度」的一句話（例：「選一個 bug 只在邊界條件
出現的電路」），因為那決定測不測得到重點；但「哪些電路符合、邊界在哪、
怎麼測到」全部留給它。

另外：改題目要**開新對話**。舊 session 已經吃進詳細版全文，
補一句「改成這個」沒用，前面的細節還在 context 裡。
