# 本地模型能力評估

實測 Qwen3.8-27B 的真實能力邊界，以及日後測新模型的標準。

---

## 結論：本地模型適合當顧問，不適合代工

| 用途 | 表現 |
|---|---|
| **STM32/RTOS 觀念題** | ✅ **A/A+** — 答得出 D-Cache 一致性、優先權反轉的極限、ISR 誤用的底層原理 |
| **審 code、找 bug** | ✅ 貼給它看，20-30 秒回應 |
| **單一模組**（規格明確、能寫測試） | ✅ 可行 — ringbuf 實測 3098 項測試 0 失敗 |
| **開放式專案** | ❌ **不行** — 見下方對比 |

---

## 🔴 決定性的對比（2026-08）

同一塊板子（STM32H7S78-DK）、同一個人操作：

| | 任務 | 結果 |
|---|---|---|
| **雲端 Claude** | 俄羅斯方塊跑在板子上（遊戲邏輯 + LCD 顯示 + 觸控輸入） | **1 小時完成，能玩** |
| **本地 Qwen3.8-27B** | 計算機（相對簡單） | **一整晚未完成** |

**難的做完了，簡單的沒做完。** 差距不是任務難度，是能力。

實際差距 **10-20 倍以上**，不是我先前估的 5 倍。

### 為什麼差這麼多

單一模組測試（ringbuf）本地表現很好，但那是**封閉任務**：
規格明確、輸入輸出清楚、能寫測試驗證。

開放式專案完全不同：

| 需要的能力 | 本地的問題 |
|---|---|
| **一次做對的機率** | 錯一次多幾輪，複利放大 |
| **判斷方向** | 走錯路徑浪費幾小時 |
| **跨檔一致性** | 會前後矛盾（同檔案 `peek` 寫對、`count` 寫錯） |
| **長程規劃** | 4 個檔案常只做完 2 個 |

這是**後訓練（agent RL）**的差距，換模型或調參數補不上。

## 📏 測新模型的標準

**「能不能在 STM32 開發板上做出一個能用的計算機」**

這個任務的要求：
- 理解開發板（LCD、觸控、boot 流程）
- 建專案、設定 CubeMX
- 寫 UI + 計算邏輯
- 編譯、燒錄、除錯
- 跑得起來

**做得出來 = 合格，可以考慮代工用途。**
**做不出來 = 維持顧問定位。**

---

## 什麼樣的模型有機會

搜尋（2026-08）顯示，真正能做 long-horizon 任務的都是幾百 B 的 MoE：

| 模型 | 參數 | Q4 大小 | 32GB 硬體 |
|---|---|---|---|
| GLM-5.2 | 753B MoE | ~380GB | ❌ |
| Kimi K2.6 | ~1T MoE | ~500GB | ❌ |
| Qwen3-Coder-480B | 480B | ~240GB | ❌ |

> GLM-5.2 專為 long-horizon software engineering 調校：全 codebase 除錯、
> 自主自我修正、多步驟 agent 執行 —— **這些在較弱的模型上會崩潰**

**值得留意的訊號**（日後挑模型時看這些）：
- 模型卡片明確標榜 **agentic / tool-use 後訓練**
- 除了 SWE-bench 還報 **多輪、長程任務**的分數
- 參數量在 30B-80B 之間但專為 agent 調校的

## 現在的合理分工

```
開發專案         → 雲端 Claude
問原因、審 code   → 本地（免費、秒回、離線）
單一模組         → 本地可行，但邊界計算要複查
隱私敏感、大量重複 → 本地
```

**本地環境沒有白費** —— 它的甜蜜點是顧問而非代工。
訂閱費花在刀口上，瑣事交給本地。

---

## 換模型時怎麼測

1. 用同一塊板子、同一個計算機任務
2. 記錄：完成時間、要人介入幾次、程式碼能不能直接用
3. 對照本檔的基準

⚠ 不要用「單一模組」測試判斷代工能力 —— 那會高估。
ringbuf 測試本地拿 3098 項 0 失敗，但實際專案做不完。
