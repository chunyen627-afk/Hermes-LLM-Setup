# 用戶端設定

新電腦要連 GPU 主機跑 LLM，照這份做。

---

## 前置需求

- Python 3.x（橋接器用，只用標準函式庫，不用裝套件）
- [Hermes Agent](https://hermes-agent.ai)（桌面版或 CLI）
- 跟 GPU 主機在同一個網路（ZeroTier 或區網）

---

## 步驟

### 1. 確認連得到 GPU 主機

```bash
curl -s -m 10 http://<GPU主機IP>:8001/v1/models
```

回傳 JSON 就是通了。連不到 → 檢查：
- GPU 那台的 llama-server 有開嗎（跑 `0-MENU.bat`）
- 兩台在同一個 ZeroTier 網路嗎
- `ping <GPU主機IP>` 通嗎

### 2. 跑橋接器

複製 `client/hermes_bridge.py` 過去，然後：

```bash
python hermes_bridge.py <GPU主機IP>
```

看到這樣就對了：
```
bridge: localhost:1234 -> http://10.35.219.64:8001
每次推論會印一行 —— 有印就代表走本機，不是雲端。
每 300 秒印一行 context 用量。
```

**這個視窗要一直開著。** 可以用 `START-BRIDGE.bat` 包一層方便雙擊。

> 想關掉 context 定期回報：`python hermes_bridge.py <IP> 0`

### 3. 設定 Hermes

先找到**正確的**設定檔（有兩個容易搞混）：

```bash
hermes config path
```

通常是 `C:\Users\<你>\AppData\Local\hermes\config.yaml`，
**不是** `C:\Users\<你>\.hermes\config.yaml`。

改成：

**⚠ 桌面版出廠預設是 Google Vertex**，不是本地。裝完一定要改，
否則會噴 `HTTP 400 Malformed publisher model`（見『踩過的坑』#15）。

最省事的做法是用 CLI 一次設完（會寫進正確的那個 config）：

```bash
hermes config set model.provider lmstudio
hermes config set model.default qwen38_mtp
hermes config set model.base_url http://127.0.0.1:1234/v1
hermes config set model.context_length 180224
hermes config set display.language zh-hant

# 長任務必備：不然模型跑編譯會等你按確認，60 秒後被擋掉
hermes config set approvals.mode off
hermes config set approvals.destructive_slash_confirm false
hermes config set agent.subagent_auto_approve true

# 壓縮預設是關的，門檻也不是 80% 而是 50%
hermes config set compression.enabled true
hermes config set compression.threshold 0.8
```

改完的 `config.yaml` 應該長這樣：

```yaml
model:
  provider: lmstudio          # ⚠ 不要選 ollama / vertex，那些走雲端
  default: qwen38_mtp         # 要跟伺服器的 --alias 一致
  base_url: http://127.0.0.1:1234/v1   # 橋接器，不是 :8001
  context_length: 180224      # 要跟伺服器的 --ctx-size 一致

compression:
  enabled: true               # 快滿時自動壓縮，不會撞牆
  threshold: 0.8              # 144K 觸發，留 36K 緩衝

approvals:
  mode: 'off'                 # 長任務必關，否則編譯驗證會被擋

code_execution:
  max_tool_calls: 100         # 預設 50，長任務不夠
```

**改完要重啟 Hermes 才生效**，而且**已經開著的對話不會跟著換** ——
session 會凍結建立當下的設定（見『踩過的坑』#16），要開新對話。

桌面版也可以在 GUI 選：**模型選單 → LM STUDIO → qwen38_mtp**，
但**要在有進行中對話的聊天畫面切**才會存進去（設定頁按「套用」只是暫存）。

### 4. 驗證

```bash
hermes -z "說 ok" --yolo
```

回 `ok` 就成功。同時橋接器視窗會印：
```
[   1] 本機推論 OK  17.0s, 268 tokens, 15.7 tok/s
```

**有印這行 = 確定走本機，不是雲端。**

⚠ 第一次會很慢（30-60 秒），因為要重新處理整個 prompt。
第二次之後 cache 命中就快很多。

## 也想用 Claude Code？

可以（同樣透過橋接器），但**實測效果明顯比 Hermes 差** —— 見主 README 的對照表。
主因是 Claude Code 帶 36 個工具定義，把 context 吃掉一半。

真要用的話設這些環境變數再啟動：
```bat
set "ANTHROPIC_BASE_URL=http://<GPU主機IP>:8001"
set "ANTHROPIC_AUTH_TOKEN=lmstudio"
set "ANTHROPIC_MODEL=qwen38_mtp"
set "ANTHROPIC_SMALL_FAST_MODEL=qwen38_mtp"
claude --dangerously-skip-permissions
```
注意 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 也要設成跟伺服器一致，否則它會用預設的
200K 假設，auto-compact 時機會錯。

## 常見問題

**Q: 橋接器一直印 `ERR /api/v1/models 404`**
舊版才會，新版已把探測路徑靜默處理。更新 `hermes_bridge.py`。

**Q: `API call failed after 3 retries: Connection error.`**
不是網路問題，是橋接器沒跑或沒補 `tools` 能力。確認橋接器有開。

**Q: Hermes 顯示的模型不是 qwen38_mtp**
provider 選錯了。要選 **LM Studio**，不是 Ollama（那個走雲端）。

**Q: 對話跑到一半突然爆掉**
`context_length` 設得比伺服器大。用 `3-CHECK-CTX.bat` 查實際值。
