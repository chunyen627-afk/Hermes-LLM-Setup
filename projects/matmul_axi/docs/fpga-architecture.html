xSPI 加速器架構

STM32 透過 xSPI 存取 FPGA 上的 BF16 矩陣加速器。這張圖是 2026-08-31 的實際狀態 —— 實線是已經存在的 RTL，虛線是還沒建的部分。

xSPI 實體訊號 AXI4 DDR4 競爭路徑 已有 RTL 尚未建立
圖上唯一的競爭點是 DDR4 那條紅線 —— xspi_slave.m_ddr_*（灌權重）和 matmul_top.m_axi_*（讀權重）都要打同一顆記憶體，而且位寬差 16 倍。 仲裁和寬度轉換都交給 Xilinx IP，兩個自己寫的模組維持標準 AXI4 介面不動。

三條資料路徑

設定 / 啟動

m_reg_* → s_axi_*。STM32 寫 0x9000_0000 區段設參數、按 start、讀 STATUS。32-bit 直連，只有一個 master，不需要仲裁。

權重進出 DDR4

m_ddr_* 經 width converter 進 interconnect。這條跟加速器讀權重共用 DDR4，是唯一需要仲裁的路口。

Activation 直通

matmul_top 已預留 xspi_x_valid/data/full，但 xspi_slave 沒有對應輸出埠。X_FROM_XSPI=0，這條還沒接。

驗證分層

模組層

iverilog + simcheck.py。每改一次 RTL 跑一次，零點幾秒。Xilinx IP 絕對不進這一層 —— 那是加密 SystemVerilog，只能用 xsim，會讓迭代從零點幾秒變成幾十秒。

整合層

Vivado block design + xsim。模組都通過之後才做一次，慢一點無所謂。驗的是「接起來對不對」，不是「模組自己對不對」。

上板

ILA / UART 量真實時序和加速比。這是「雛形完成」的定義 —— 不是 gate 全綠，是真的比 STM32 CPU 快。
