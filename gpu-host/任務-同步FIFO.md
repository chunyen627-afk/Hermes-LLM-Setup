# 任務：做一個同步 FIFO，證明它在邊界條件下不會出錯

做一個 **深度 8、寬度 8 bit 的同步 FIFO**（讀寫同一個 clock domain），
然後證明它是對的。

驗收標準只有一個：**你能拿出證據說服我它不會壞**，不是「跑起來看起來正常」。

---

## 規格

- `depth = 8`、`width = 8`
- 介面：`clk`, `rst_n`, `wr_en`, `wr_data[7:0]`, `rd_en`, `rd_data[7:0]`,
  `full`, `empty`
- 先進先出，讀出順序必須跟寫入順序一致
- `full` 時再寫 → 資料不可以被吃掉或覆蓋既有內容
- `empty` 時再讀 → 不可以吐出垃圾
- 同一個 cycle 同時 `wr_en` 和 `rd_en` 要有明確定義的行為（你自己決定怎麼做，
  但要寫進文件並且測到）

---

## 這題真正在測什麼

UART 那題是**串列協定**，錯了通常整包都錯，很明顯。

FIFO 不一樣 —— **它的 bug 只在邊界出現**：

- 剛好寫滿的那一刻
- 剛好讀空的那一刻
- 寫指標繞回 0 的那一刻（wrap around）
- 同時讀寫且剛好 full / 剛好 empty

**這些情況不會自己發生。** 隨機丟資料進去跑一萬個 cycle，可能一次都碰不到
「full 的時候又來一筆寫入」。你要**刻意製造**這些情況。

---

## 必須做到的驗證

**至少涵蓋這 7 個情境**，每個都要有可判定的 PASS/FAIL 輸出：

1. 寫 8 筆填滿 → `full` 要拉起來
2. full 之後再寫 3 筆 → 讀出來還是原本那 8 筆，順序不變
3. 讀空 → `empty` 要拉起來
4. empty 之後再讀 3 次 → 不可以吐出垃圾（定義好你期望什麼）
5. 寫滿→讀空→再寫滿，跑兩輪（測指標 wrap around）
6. 交錯讀寫 50 次以上，用獨立的 Python model 比對每一筆
7. 同 cycle 同時讀寫，在 full / empty / 半滿三種狀態下各測一次

**第 6 項的「獨立 model」是重點**：用 Python 的 `collections.deque` 自己
模擬一份 FIFO，跟 RTL 的輸出逐筆比對。**不要用 Verilog 再寫一個 FIFO 來比**
——那可能跟 DUT 犯一樣的錯。

## 交付

1. `fifo.v` — RTL
2. `tb_fifo.v` — testbench，7 個情境都要有
3. `model_check.py` — 獨立的 Python 參考模型比對
4. **一張波形圖** — 挑「寫滿的瞬間」或「wrap around 的瞬間」畫出來，
   自己看過並說明你從圖上看到什麼
5. **一份結果摘要** — 7 個情境各自 PASS/FAIL，有 FAIL 就說清楚為什麼

---

## 三件不要做的事

- ❌ 沒跑過就說「應該可以」
- ❌ 測試沒過就改測試讓它過（要改的是 RTL）
- ❌ 圖畫出來沒看就說「波形正常」

如果某個情境你試了做不出來，**明確寫出來**，不要無聲跳過。
誠實說「這個我沒做到」比假裝做完有價值。
